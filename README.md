## A- Description :eye:

**MAEL Scan** is a mobile phone application :iphone: (soon, a Raspberry Pi version <img src="https://cdn.simpleicons.org/raspberrypi/FFFF" width="24" height="24" style="vertical-align: middle;" />) that allows the student to scan QR codes created by their teacher with **MAEL Gen** and listen to their content :speaker:.   
Its interface is designed to be used by a child, from the age of 4 :baby:.   
It only includes 3 large buttons by default.

**MAEL Scan** allows students who do not have any “talking device” at home to listen to the language being studied within an educational context designed by their teacher :100:. It therefore allows the teacher to **boost their language teaching** :chart_with_upwards_trend:.

**Potentially, 55 languages can be implemented!** :astonished:

:fr: :gb: :es: :portugal: :brazil: :it: :de: :ru: :jp: :cn: :kr: ...

## B- Features :clipboard:

- **Scan** :speaker: : Starts scanning the QR code and then vocalizes its content.
- **Listen again** :curly_loop: : Allows listening again without re-scanning.
- **Listen more slowly** :snail: : Allows listening again without re-scanning, but more slowly (does not work with mp3 files).
- **“MP3” playback** :musical_note: : When scanning, if the link points to an mp3 file, the student will hear that file.
- **Special modes** : These are syllable libraries in mp3 format (integrated into MAEL Scan) because reading a single syllable is sometimes of poor quality with synthetic speech :unamused:. There are:
    - the syllables of the Consigny bilingual alphabet book (in French and Spanish)
    - the syllables of the “Borel-Maisonny” method (very commonly used syllables, associated with gestures intended to help children with dysorthography)

## D- Operating principle :gear:

*(To help understand the code)*

---

---

1. **MAEL Scan** scans a QR code
1. It **decrypts** the content of the QR code (algorithm already written in Kotlin :+1:).
1. It extracts the **prefix** and the **suffix** using [**regex**](https://en.wikipedia.org/wiki/Regular_expression).
1. It deduces the **language**, the **country**, and the **mode** (or whether it is an **mp3**).
1. It configures :gear: the phone’s **text-to-speech** module according to the language and country (or selects the mp3 playback module)
1. It configures :gear: the mode (Reading / Hide / Dictate / Spell) and vocalizes :speaking_head: the text as requested. 
1. If it is a special mode, it retrieves the corresponding audio (integrated into the app) :outbox_tray:.

[Additional document](./readme_assets/MAEL_Scan-Pseudo_code_Kotlin.pdf) :spiral_notepad:

>*Anecdote* : the *MIT App Inventor* version does not have the necessary functions to decrypt the content of the QR code. I had to write the algorithm in JavaScript to integrate it into a web page used by the **Web** module of *MIT App Inventor*.  
What a detour!!! :grimacing:   
⟶ Another reason for migrating to Kotlin <img src="https://cdn.simpleicons.org/kotlin/FFFF" width="24" height="24" style="vertical-align: middle;" />.

## E- Features to be developed :rocket:

1- **“Dictation” mode**

- The current _dictation mode_ (vocalizing the text but not displaying it) will change name and be called **“Hide mode”**. :arrows_counterclockwise:

- The new _dictation mode_ will include:

    - reading the text, but not displaying it,
    - vocalization of punctuation, and
    - display of the play–pause menu (with progress bar). :play_or_pause_button:

2- **“MP3” mode**

- Creation of a **MAEL Cloud** :cloud: with fewer limitations than Google Drive. (hosted with the **MAEL Phrase** platform).
- Addition of an option (suffix) that will indicate to **MAEL Scan** that it must keep the file :inbox_tray: so it does not have to be re-downloaded if it is scanned again.

3- **“Spell” mode**

*Preliminary explanation:*   
To spell a text, **MAEL Scan** contains a data structure holding the correspondences between letters and what should be spoken.

*Examples:*

 | Letter | What will be pronounced |
 |:--------:|--------------------|
 | A | capital A |
 | a | a |
 | é | e acute accent |
 | ç | c cedilla |

This database is very specific to each language.
In the *MIT App Inventor* version of **MAEL Scan**, this information is stored in a variable of type `dictionary` which takes the form of an **immense building :office: made of small blocks**, difficult to display (and therefore to manage).  
It seems very complicated to create 55 dictionaries of this type :face_with_spiral_eyes:, which is one of the limiting factors of *MIT App Inventor* and therefore one of the reasons for the move to Kotlin MP <img src="https://cdn.simpleicons.org/kotlin/FFFF" width="24" height="24" style="vertical-align: middle;" />.

1- **Implementation of a SQLite database <img src="https://cdn.simpleicons.org/sqlite/FFFF" width="24" height="24" style="vertical-align: middle;" />**

It would therefore be necessary to use a **SQLite** database in which each table would contain the correspondences `Letter | What will be pronounced`.

2- **Handling of ideographic writing systems** :ideograph_advantage:

How should spelling be handled for languages such as Chinese :cn:, Japanese :jp:, or Korean :kr:?

If a specialist in one of these languages is interested, he or she will be welcome! :open_hands:
